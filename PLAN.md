# Convergence — Build Plan

**Status:** Phase 3 design saved; implementation handed off to another author · **Last updated:** 2026-11-11

Convergence runs AI agent tools (MCP servers, agent skills, model-generated scripts) under a
least-privilege policy that the Linux kernel enforces (Landlock + seccomp-bpf + resource
limits), unprivileged. It can also generate that policy from observed behaviour, the way
SELinux's `audit2allow` does. It is the companion to
[Divergence](https://github.com/vignesh-chaturvedi/divergence): Divergence *detects*,
Convergence *contains*.

This file is the working plan. It is updated at the end of every phase.

---

## 1. Ground rules

- **Every claim must be reproducible.** Numbers in the README come from committed scripts and
  committed result files. Tables are generated from those files, not typed by hand.
- **Fail closed.** If a rule cannot be enforced on the running kernel, `run` refuses, unless
  `--allow-degraded` is passed, and then it prints exactly what is not enforced. A rule is
  never dropped silently.
- **No mocks for security behaviour.** Enforcement tests run against a real kernel: the Lima
  VM locally, GitHub Actions in CI. Docker Desktop is never used as evidence.
- **Never overclaim.** This is defence in depth, not a VM boundary. Gaps are written down.
- **Stack:** Python 3.12+, `uv`, `ruff`, `mypy --strict`, `pytest`. No Rust code in this
  project.
- **Commits:** plain messages in the project's own voice. No AI attribution trailers, no
  "generated by" notes in commits, PR bodies, docs, or code. AI tool config files are kept
  out of the repository.
- **Phase gate.** A phase ends only when all of these are true:
  1. lint, type check, and tests pass inside the VM;
  2. `CHANGELOG.md` and the status table in this file are updated;
  3. the work is committed locally;
  4. a summary with evidence has been given to you;
  5. **you have approved the push.** Nothing is pushed without that;
  6. after the push, the CI result has been checked and reported.

## 3. Research findings that shape the design

### 3.1 Divergence: the report we import

- The dynamic-tier runner writes schema **`divergence.sandbox/1`**: `capabilities`,
  `observations[]` (each with `capability`, `syscall`, `target`, `decoy`, `succeeded`,
  `result`), `coverage` (syscalls observed, entrypoints invoked/completed/failed,
  `confinement_enforced`, `timed_out`, …), `evidence`, and `limitations`.
- `divergence scan --json` embeds the same data under `targets[].dynamic`, plus `ran` and
  `available`.
- Capability vocabulary: `fs_read`, `fs_write`, `fs_delete`, `net_outbound`, `net_listen`,
  `proc_spawn`, `secrets_read`.
- **Divergence's tracer drops runtime noise on purpose**: `/usr/lib`, `/lib`, `/etc`,
  `/proc`, `/sys`, `/dev`, `site-packages`, `*.py`, `*.so`. It also caps observations at
  10,000. An imported report therefore describes the artifact's *interesting* behaviour,
  not every file its interpreter needs. The importer has to say this, and either merge a
  runtime baseline that Convergence observes itself, or produce a policy that will fail
  closed on runtime paths. It must not present the result as complete.
- Decoy reads and `secrets_read` are never turned into allow rules automatically. Blocked
  attempts (`succeeded: false`) show intent, not need, so they are reported but not granted.
- Divergence's holdout discipline says it "reduces but does not remove" author bias. We
  use the same wording, because the same applies here.

### 3.2 sandlock (multikernel/sandlock v0.9.1, Apache-2.0)

- Rust core, Python ctypes SDK, manylinux wheels for x86_64 and aarch64.
- **Hard minimum of Landlock ABI v6 (kernel 6.12+).** It does not run on stock Ubuntu 24.04,
  which has ABI 4.
- IP allowlisting, `/proc` virtualisation, copy-on-write, and memory/process limits run
  through a **seccomp user-notification supervisor**. That is the pattern this project must
  not use as a security boundary (TOCTOU on pointer arguments). A `no_supervisor` mode
  exists but still requires ABI 6.
- It already ships **`sandlock learn`** (observe a run, emit a profile) and an **MCP
  server**. So "policy from observation" and "sandbox over MCP" are not new ideas. The
  Prior art section must say so plainly and describe what Convergence adds: stock-kernel
  support, kernel-only enforcement, a rationale for every rule, audit2allow-style denial
  explanations, the Divergence importer, and a published escape matrix with a holdout.
- **Decision (ADR-0002, accepted in Phase 1):** do not build on sandlock. Cite it as prior art.

### 3.3 `landlock` on PyPI (Edward-Knight/landlock, MIT)

- Only `1.0.0.devN` pre-releases; the last upload was May 2025. It covers filesystem rules
  only, with no ABI 4 network rules and no scoping. Too narrow to depend on.

### 3.4 seccomp

- libseccomp is installed by default on Ubuntu 24.04 because systemd depends on it. The
  official Python bindings are not on PyPI. `pyseccomp` (ctypes) was last released in 2021.
- **Decision (ADR-0002, accepted in Phase 1):** a thin ctypes binding to libseccomp's stable C API
  (`seccomp_init`, `seccomp_rule_add`, `seccomp_arch_*`, `seccomp_export_bpf`). The filter
  is built by the maintained library, so architecture checks (x32, 32-bit compat) are not
  hand-written. Landlock gets its own small ctypes binding over its three syscalls, because
  no maintained Python package covers ABI 4.

### 3.5 MCP Python SDK

- `mcp` **2.3.0** is current (v2 line, released 2026-10-02). The v2 API differs from v1. It
  is checked against the installed package at the start of Phase 6, not written from memory.

### 3.6 PyPI name

- `convergence` is taken. `convergence-sandbox` and `convergence-mcp` were free on
  2026-11-11. Proposed: distribution `convergence-sandbox`, command `convergence`. This is
  the same pattern Divergence uses with `divergence-mcp`.

## 4. Architecture decisions

Each row becomes a short ADR in `docs/adr/` during the phase listed. "Proposed" means the
evidence gathered in that phase can still change the decision.

| ADR | Decision (proposed) | Phase |
|---|---|---|

| 0002 | Enforcement libraries: own ctypes Landlock binding plus libseccomp via ctypes. sandlock and `landlock` were evaluated and rejected | 1 |
| 0003 | Landlock ABI handling: detect at runtime, enforce the highest known ABI, map each policy rule to the minimum ABI it needs, no kernel version numbers in code | 1 |

| 0011 | Benchmark methodology | 7 |

### 4.1 Design notes to verify, not assume

1. **Layering.** Landlock covers the filesystem and TCP ports. seccomp-bpf is kernel-only:
   `SECCOMP_RET_ERRNO`, no user notification. It enforces syscall deny or allow lists, plus
   integer-argument rules that close gaps Landlock leaves open on ABI 4:
   - `socket()` domain and type. `network: none` denies `AF_INET`/`AF_INET6`, which works
     on any ABI. `SOCK_DGRAM` and `SOCK_RAW` are denied because Landlock filters TCP only.
     `AF_UNIX` `socket()` is denied unless the policy allows it: before ABI 6, abstract
     sockets are not scoped, and pathname sockets such as `docker.sock` stay reachable.
     `socketpair()` is still allowed.
   - Denied: `ptrace`, `process_vm_readv/writev`, `mount` and the new mount API,
     `unshare`, `setns`, `clone` with namespace flags, `clone3` (it takes a struct pointer,
     so it returns `ENOSYS` and libc falls back to `clone`), `io_uring_*` (its operations
     bypass syscall filtering), `bpf`, `perf_event_open`, `keyctl`, `userfaultfd`, kexec,
     `seccomp` with `NEW_LISTENER`, and `ioctl(TIOCSTI/TIOCLINUX)`.
2. **What Landlock does not restrict**, at least on ABI 4: `stat`, `access`, `readlink`,
   `chdir` (path walks and metadata reads); already-open file descriptors;
   `chmod`/`chown`/xattr/`utime`; UDP; signals and abstract unix sockets before ABI 6;
   `connect()` to pathname unix sockets (check whether a newer ABI covers this). All of
   these go into `THREAT_MODEL.md` and into `explain` output.
3. **Executing through the dynamic loader.** `ld-linux-*.so <binary>` maps the target
   instead of `execve`-ing it, so any *readable* binary may be runnable. If that holds,
   "executable paths" are only as strong as the read restrictions. Phase 3 tests this and
   the docs say what was found.
4. **`RLIMIT_NPROC` counts every process the user owns, system-wide**, not per sandbox. The
   runtime sets it to "current count + `max_processes`" at launch and documents the race.
   Fork-bomb containment also relies on the wall-clock timeout and on killing every
   descendant.
5. **Descendants that escape the process group** through `setsid` or a double fork: the
   supervisor sets `PR_SET_CHILD_SUBREAPER` and sweeps reparented descendants on timeout and
   exit.
6. **Python `preexec_fn` is unsafe in multi-threaded parents.** The CLI forks before it
   starts any thread. The MCP server uses a single-threaded spawn helper that it starts
   before any threads exist.
7. **No inherited state:** every fd except 0, 1, and 2 is closed. The environment is built
   from the policy, empty by default. No controlling tty is passed in.

## 6. How work runs

- Code is edited on macOS and **executed only in the VM**. `scripts/vm.sh test` runs
  `uv run …` in the guest with `UV_PROJECT_ENVIRONMENT=$HOME/.venvs/convergence`, so the
  virtualenv lives on the guest's ext4 disk, not on the virtiofs mount. Tests create their
  sandboxes under the guest's `/tmp`.
- CI runs lint and type checks, then the tests on `ubuntu-latest` (x86_64, Ubuntu 26.04),
  `ubuntu-24.04` (x86_64), and `ubuntu-24.04-arm` (arm64), for Python 3.12 and 3.13. A
  separate job boots the stock Ubuntu 24.04 kernel in a nested QEMU/KVM VM and runs the
  tests there. Each job uploads its `doctor --json` report. From Phase 4 on, the dev escape
  matrix runs too. The holdout job runs only on manual dispatch.
- Only one VM runs at a time, because the host has 8 GB of RAM.

## 7. Phases

Every phase ends with the phase gate from §1: a local commit, a summary, **your approval**,
the push, and then a CI check.

### Phase 0 — Bootstrap

**Goal:** an empty but real project that lints, type-checks, and tests in the VM and in CI.

- `pyproject.toml` (uv, src layout, `convergence` entry point printing `--version`), ruff,
  mypy (strict) and pytest configuration, `uv.lock`.
- `scripts/vm.sh`: `create`, `provision` (uv and build dependencies in the guest), `shell`,
  `test`, `check`.
- CI workflow: lint and type check, plus tests on both CI architectures.
- `LICENSE` (Apache-2.0, matching Divergence), `CHANGELOG.md` (Keep a Changelog),
  `.gitignore`, an ADR template, and ADR-0001.
- A README stub that states the real status: pre-alpha, nothing enforced yet.

**Exit gate:** `scripts/vm.sh check` is green, and CI is green after the push.

### Phase 1 — `doctor` and the capability probe (Milestone 1)

**Goal:** know exactly what the kernel can enforce before any enforcement code exists.

- Build `docs/landlock-abi.md` from the kernel documentation, with sources: which access
  rights and features each ABI version adds. Filesystem rights through `REFER`,
  `TRUNCATE`, and `IOCTL_DEV`; TCP bind/connect by port; signal and abstract-socket
  scoping; and whatever later ABIs add. ABIs newer than the code knows are handled by
  enforcing the highest known version and reporting that.
- ctypes Landlock binding: ABI query (and errata query if the kernel offers one),
  `create_ruleset`, `add_rule`, `restrict_self`.
- ctypes libseccomp binding: library version and API level, filter building, BPF export.
- **The probe proves features live instead of trusting version numbers.** Each feature is
  applied in a throwaway forked child, and a known-forbidden operation must fail. For
  example, Landlock restricted to one directory must make reading `/etc/hostname` fail with
  `EACCES`. Probing must never confine `doctor` itself, and a test checks that.
- Informational probes: kernel release, architecture, LSM list, whether the process is
  already seccomp-filtered (for example inside a container), whether no-new-privs is
  already set, root (warned; `run` will refuse it), Yama, user-namespace restrictions, strace
  version, libseccomp version.
- `convergence doctor`: a human-readable table and `--json` (`convergence.doctor/1`),
  including a "will / will not be enforced on this machine" section. It exits non-zero when
  the minimum enforcement set is unavailable.
- ~~Create a second VM with the HWE kernel~~ — dropped (ADR 0003): the CI kernels already
  have ABI 8. Instead, CI gains an explicit `ubuntu-24.04` job and a nested-VM job on the
  stock 24.04 kernel.
- Record `doctor` output in `docs/evidence/doctor/`: the GA VM now; the CI kernels from the
  uploaded artifacts after the push.
- ADR-0002 and ADR-0003.
- The `doctor-v1` JSON Schema moves to Phase 2, where the schema tooling arrives.

**Exit gate:** `doctor` runs on the GA VM and on every CI kernel, and the outputs are
committed. **If a CI kernel lacks Landlock or seccomp, stop and report it with evidence.**

### Phase 2 — Policy schema, `validate`, and `explain` for policies (Milestone 2)

Versioned schema `convergence.policy/1`, in YAML or JSON. A JSON Schema is exported to
`schemas/`. Draft shape:

```yaml
version: 1
filesystem:
  read:    [/usr, /lib, /etc/ld.so.cache]   # directories are recursive, files are exact
  write:   [/tmp/work]                      # read-write
  execute: [/usr/bin/python3.12]            # implies read
network:
  mode: none            # none | ports
  connect_tcp: []       # ports only: Landlock filters by port, not host
  bind_tcp: []
  unix_sockets: deny    # deny | allow
syscalls:
  mode: deny-list       # deny-list (default allow list minus deny) | allow-list (strict)
  deny: []
  allow: []
resources:
  cpu_seconds: 10
  address_space_mb: 512
  max_processes: 32
  max_file_size_mb: 64
  max_open_files: 256
  wall_clock_seconds: 30
environment:
  pass: []              # names passed through from the caller; default none
  set: {}
```

- ADR-0004 pins down the semantics:
  - path canonicalisation at load time, including symlinks in policy paths;
  - nonexistent paths are an error unless marked optional;
  - the exact Landlock rights for each bucket, including rights that depend on the ABI;
  - how `/proc` and `/dev` are handled;
  - unknown keys are rejected;
  - versioning.
- `convergence validate p.yaml`: schema and semantic checks. It warns on dangerous grants
  such as `/`, `$HOME`, `docker.sock`, writes to `/proc`, and `/dev`.
- `convergence explain --policy p.yaml`: reports every rule as ENFORCED (and by which
  mechanism), PARTIAL (and what is missing), or UNENFORCEABLE on this kernel. Table and JSON
  output. `run` will refuse UNENFORCEABLE or PARTIAL rules unless `--allow-degraded` is
  passed.
- `docs/policy.md` with examples. Host and IP allowlisting is listed as out of scope for
  v1, with the reason: Landlock cannot express it.

**Tests:** schema round-trips and rejections. The enforceability logic is tested against
every ABI level as pure logic, and also against the live kernel.

**Exit gate:** `validate` and `explain` are correct on the GA-kernel VM and on the CI
kernels, and the schema is committed.

**As built (Phase 2):**
- Dependencies are pydantic and PyYAML, resolved with a 14-day release cooldown
  (`exclude-newer = "14 days"`).
- `explain` gained `--assume-abi N` to assess against a hypothetical kernel.
- Two findings that shape later phases:
  - Landlock does not control `stat`, `chmod`, `chown`, `setxattr`, or `utime` on any ABI,
    so `explain` reports a metadata gap on every kernel. Phase 4 decides whether seccomp
    should mitigate it, using benign-control data.
  - On ABI 4, allowing DNS over UDP makes a policy `unenforceable`, because UDP cannot be
    limited to port 53 before ABI 10.

### Phase 3 — Threat model, escape matrix, and benign controls, written before the runtime (Milestone 3)

- **Draft `THREAT_MODEL.md`.** The attacker has arbitrary code execution as the sandboxed
  tool, the same uid as the user, and knows the policy. Their goals: read secrets, write
  outside the grant, persist, exfiltrate, escalate, deny service to the host, or interfere
  with other processes. The model states what is defended. Non-goals: kernel exploits, side
  channels, host or IP allowlisting, covert channels over allowed ports, misuse of
  resources the policy itself grants.
- **Case format (YAML):** id, category, description, policy, payload, oracle, expected
  verdict (`blocked` / `allowed`), expected mechanism (informational), and platform
  constraints.
- **External oracles only.** A payload's report about itself is never trusted:
  - canary secret files, whose contents must not appear in any output or written file;
  - canary paths outside the writable area, which the harness checks afterwards;
  - TCP listeners owned by the harness, which must see no connection;
  - sentinel processes, whose state must not change (ptrace, signals);
  - process counts and wall-clock time, for fork bombs;
  - environment canaries planted in the supervisor's own environment.
- **Categories** (a superset of the spec's list):
  - reading and writing outside the allowed paths;
  - symlink, hardlink, `..`, and rename/`REFER` traversal;
  - `/proc/self` tricks (`mem`, `fd`, `root`, `cwd`, `environ`, reopening `exe`) and
    `/proc/<pid>` of a parent or sibling;
  - running disallowed binaries directly, through an interpreter, and through the dynamic
    loader;
  - setuid binaries (no-new-privs);
  - TCP connect/bind to disallowed ports over IPv4 and IPv6, UDP, raw sockets;
  - unix sockets to host services;
  - `ptrace` and `process_vm_readv`;
  - `mount`, `unshare`, `setns`, namespace `clone` flags, `clone3`;
  - `io_uring`, `bpf`, `perf_event_open`, `keyctl`, `userfaultfd`;
  - `TIOCSTI` terminal injection;
  - signals to processes outside the sandbox;
  - fork bombs, memory and CPU exhaustion, the file-size limit, fd exhaustion;
  - surviving the timeout via `setsid` or a double fork;
  - environment and inherited-fd leakage.
- **Benign controls** (≥ 10): a Python stdlib script over a project directory; git
  operations on a fixture repo; shell pipelines (grep/find/sed); tar and gzip; Python
  `sqlite3`; an HTTP client to a harness server on an allowed port; a server binding an
  allowed port; a real stdio MCP server, built with the `mcp` SDK, answering tool calls;
  and similar workloads.
- **Split:** about two thirds dev and one third holdout, stratified by category. Targets:
  at least 45 dev attacks, 20 holdout attacks, and 10 controls. The holdout is sealed by a
  committed SHA-256 manifest. The runner refuses to run the holdout without an explicit
  one-time flag, and every holdout run is appended to a log with its commit SHA.
- **Validity check:** every attack must succeed when run unconfined, with a bare
  `subprocess`. A case that fails unconfined proves nothing and is rewritten. The unconfined
  results and the "initially failing" baseline against the unimplemented runtime are
  committed.
- ADR-0005. The CI escape job is added, allowed to fail until Phase 4.

**Design handoff (Phase 3):** the threat model and the escape-matrix design are written
and saved — [`THREAT_MODEL.md`](THREAT_MODEL.md), [ADR 0005](docs/adr/0005-escape-matrix-design.md),
and the implementation spec [`escape/README.md`](escape/README.md). The case files,
oracles, runner, controls, sealed holdout, and the committed unconfined-validity and
initially-red baselines are to be built against that spec by the next author. The
holdout being authored here and the runtime being written afterwards by someone else
makes the two more independent than one author doing both (ADR 0005).

**Exit gate:** the case counts are met, 100% of attacks are proven to work unconfined, and
the baseline report is committed.

### Phase 4 — Runtime enforcement (Milestone 4)

- `convergence run --policy p.yaml [--allow-degraded] [--timeout S] [--json] -- <cmd…>`.
- **Parent:** load and validate the policy, check enforceability (refuse, or print what is
  degraded), open `O_PATH` fds and build the Landlock ruleset, build the seccomp BPF with
  libseccomp, resolve the executable, compute rlimits, then fork.
- **Child:** setsid, rlimits, `PR_SET_NO_NEW_PRIVS`, `landlock_restrict_self`, install
  seccomp, close fds, `execve` with the policy's environment (ADR-0006).
- **Supervisor:**
  - enforces the wall-clock timeout, then kills the process group and sweeps subreaper
    descendants;
  - captures stdout and stderr with byte limits and marks any truncation;
  - records the exit status or signal and resource usage;
  - saves a run record (`convergence.run/1`) under `$XDG_STATE_HOME/convergence/runs/`.
- **Denial capture (ADR-0007):** when strace is available, `run` traces failed syscalls
  (follows forks, decodes paths, one file per pid). This is outside the enforcement
  boundary: if the tracer dies, the sandbox still holds. Each denial is attributed:
  - `EACCES` on a path outside the policy → Landlock filesystem;
  - `EACCES` on a disallowed port → Landlock network;
  - `EPERM` on a denied syscall → seccomp;
  - `EAGAIN` from fork near the limit, `SIGXCPU`, `SIGXFSZ` → rlimits;
  - kill on deadline → timeout.

  Failures that cannot be attributed are reported as unattributed, not guessed.
  `--no-trace` gives the lowest overhead without denial detail. Both modes are benchmarked.
- Iterate until every dev attack is blocked. Any case that still gets through is documented
  as a known limitation in `THREAT_MODEL.md`, with the reason.
- **Then run the holdout exactly once.** The raw results are committed and reported as they
  are. Fixes made afterwards are listed separately and never overwrite the original holdout
  result.

**Exit gate:** dev escape rate is 0% or every exception is documented; the controls pass
under hand-written policies; the holdout result is published; the CI escape job is made
required.

### Phase 5 — Observe, generate, Divergence importer, and denial explanations (Milestone 5)

- `convergence observe [--out obs.json] -- <cmd…>`: runs the command under strace. It
  records files opened (with flags and results), directory operations, executables run,
  ports connected and bound, and the full syscall set. Event ids make every observation
  citable. Schema: `convergence.observation/1`.
  - Observe mode is **not a sandbox**. It applies no-new-privs, rlimits, and the timeout,
    and warns loudly. Running it in a disposable VM is recommended. TOCTOU does not matter
    here because nothing is being enforced (ADR-0008).
- `convergence generate --from obs.json [--out p.yaml]`: emits a minimal policy and a
  **rationale for every rule**, citing the event ids that justify it (ADR-0009).
  - Exact file grants by default. A directory is granted only when the observed operation
    needs one: readdir, create, unlink, or rename.
  - Runtime trees such as an interpreter's stdlib may be collapsed to a directory, with a
    stated rationale ("212 files read under /usr/lib/python3.12").
  - Never collapses to `/`, `$HOME`, or `/etc`. Secrets and decoys are never granted; they
    are listed as warnings instead.
- **Divergence importer:** `convergence import divergence <report.json>` accepts both
  `divergence.sandbox/1` runner reports and `divergence scan --json` output. It maps
  capabilities to observation events, marks completeness as `partial`, never grants
  decoys, secrets, or blocked attempts, and asks for a runtime baseline or warns that the
  policy will fail closed on runtime paths. It is tested on reports produced by actually
  running Divergence in the VM, with Divergence's commit SHA recorded as provenance.
- `convergence explain --run <id>`: for each denial it gives the cause, the rule that blocked
  it, the **smallest policy change** that would permit it (as a YAML diff), and a risk note
  (for example "this grants write access under $HOME"). It never applies the change itself.
- **False-denial rate:** for each control, observe with input A, generate, then run with
  input A (*same-input FDR*) and with a different input B (*varied-input FDR*, which
  measures how incomplete the observation was). Both numbers are published.

**Exit gate:** every control passes with the same input, both FDR numbers are committed, and
the importer passes on real Divergence output.

### Phase 6 — MCP server (Milestone 6)

- Check the `mcp` 2.x server API from the installed package first (ADR-0010).
- `convergence mcp`, over stdio. Streamable HTTP is optional and bound to localhost only.
- Tools:
  - `run_sandboxed(command, policy, timeout_s)` returns the exit code, truncated output,
    denials, and `run_id`;
  - `generate_policy(observation)` returns a policy and per-rule rationale;
  - `explain_denials(run_id)` returns causes and suggested minimal changes;
  - `check_policy(policy)` returns which rules this kernel can enforce.

  `observe` runs commands unconfined, so it is not exposed unless the server is started with
  an explicit flag.
- `command` is an argv list and never goes through a shell. The policy is validated against
  the schema. No call runs without a policy, and there is no default allow.
- A single-threaded spawn helper starts with the server, so the per-call cost is sandbox
  setup, not interpreter startup. That cost is measured.
- Tests: an in-memory client session, a stdio end-to-end test with the SDK client, and a
  subset of the escape matrix run through the MCP path.

**Exit gate:** all four tools work from a real MCP client, and per-call latency is recorded.

### Phase 7 — Benchmarks (Milestone 7)

- Configurations, all on the same machine:
  - bare `subprocess` (baseline);
  - Convergence through the library API in a warm process, with and without denial tracing;
  - Convergence CLI, cold, including interpreter startup;
  - one Convergence call through the MCP server;
  - `bwrap` with a comparable setup;
  - `docker run --rm` with a pinned minimal image, cold and warm.

  Docker is `docker.io` installed **inside the VM**, never Docker Desktop.
- Workloads: `/bin/true`, `python3 -c pass`, and a small file-processing script.
- At least 200 measured runs per configuration after a warmup. Reported: p50, p95, p99,
  mean, and standard deviation. Hardware, kernel, and tool versions are recorded. JSON is
  authoritative and Markdown is generated from it. One command regenerates everything.
- Environments: the arm64 VM (Apple M2, vz) and CI x86_64. CI results are labelled as coming
  from a noisy shared runner.
- "Cold" is defined in ADR-0011. For Docker it means the first run after a daemon restart
  and a page-cache drop; that needs sudo in the VM, for the benchmark harness only.
- The numbers are published whatever they turn out to be.

**Exit gate:** the table regenerates from one command, and the README table is generated
from the results.

## 8. Metrics

- **Escape rate** = attacks not blocked ÷ attacks, reported separately for dev and holdout
  and per kernel (GA 6.8 / ABI 4, HWE, CI x86_64, CI arm64), with Wilson 95% intervals.
- **False-denial rate** = controls that fail under their generated policy ÷ controls,
  reported for both same input and varied input.
- **Latency:** p50, p95, and p99 for each benchmark configuration.

## 9. Risks and open questions

1. **CI kernels differ from the VM.** They have Landlock ABI 8 (checked in Phase 0), not the
   stock 24.04 ABI 4. The nested-VM CI job covers ABI 4; if KVM is unavailable on the runner,
   ABI 4 evidence comes from the local VM only and the README says so.
2. **ABI 4 cannot scope signals or abstract unix sockets.** `AF_UNIX` `socket()` is denied
   by default as a mitigation. Signals to same-uid processes outside the sandbox cannot be
   blocked on ABI 4 without a PID namespace, so this is a documented limitation on stock
   24.04 and is enforced on ABI ≥ 6.
3. **The dynamic-loader trick** may let any readable binary run (see §4.1 note 3).
4. **`RLIMIT_NPROC` is per user**, not per sandbox (see §4.1 note 4).
5. **strace is not installed everywhere.** `doctor` reports it. Runs still enforce the
   policy, but denial detail is unavailable without it.
6. **Observation is incomplete by nature.** The varied-input FDR measures how much that
   costs.
7. **Holdout independence.** The same author writes both the holdout and the runtime.
   Sealing the holdout by hash before runtime work starts reduces this bias but does not
   remove it. Option: you or another contributor write or review the holdout cases.
8. **Host RAM is 8 GB**, so only one VM runs at a time.
9. **PyPI publication needs your action** to set up the trusted publisher.
10. **Metadata operations outside the grants** (`chmod`, `chown`, `setxattr`, `utime`,
    `stat`) are not controlled by Landlock on any ABI. Mitigating them with seccomp may break
    common tools (`touch`, `tar`, `pip`). Decide in Phase 4, with the benign controls as
    evidence.
11. **UDP on stock 24.04.** DNS needs UDP, and ABI 4 cannot limit it to port 53. Networked
    policies on stock 24.04 will need `--allow-degraded`, or DNS over TCP only.
