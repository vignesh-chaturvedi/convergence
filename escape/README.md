# Escape matrix

This directory is the escape matrix: attack cases and benign controls that measure whether
Convergence's enforcement holds, on a real kernel, with no mocks. The decisions behind it are
in [ADR 0005](../docs/adr/0005-escape-matrix-design.md); the boundary it tests is in
[THREAT_MODEL.md](../THREAT_MODEL.md).

> **State (Phase 3 complete):** the harness, ten benign controls, **47 distinct development
> attacks** (generated by [`build_cases.py`](build_cases.py)), and a **sealed 26-case
> holdout** written independently of the generator and of the runtime. On the stock Ubuntu
> 24.04 kernel, 45 development attacks are valid unconfined and 2 are `not-testable` (the
> host refuses raw sockets and TIOCSTI); all 26 holdout attacks are valid unconfined. The
> confined baseline is red until `convergence run` exists (Phase 4).
>
> Results are in [results/](results/README.md).

## Principles (do not weaken these)

1. **External oracles only.** A case's verdict comes from ground truth the harness controls,
   never from what the payload says about itself. See [Oracles](#oracles).
2. **Validity first.** Every attack must be shown to *escape when unconfined* before it
   counts, and every control to *succeed* unconfined. A case that fails this proves nothing.
3. **Real kernels only.** Cases run under the Lima VM and in CI. No mock ever stands in for
   Landlock, seccomp, or rlimits.
4. **ABI-aware.** A case names the mechanism and minimum ABI expected to stop it. Below that
   ABI, an escape is a *documented limitation*, not a failure.
5. **The holdout is sealed and not consulted during Phase 4 tuning.**
6. **Nothing that did not run is counted as a pass**, and an attack only counts as
   contained if it *reached* its attempt (see [The reached marker](#the-reached-marker)).
7. **What the host already prevents is not credited to Convergence.** A case that needs
   something the host refuses is `not-testable` (see [Host preconditions](#host-preconditions)).

because `pyproject.toml` sets pytest's `pythonpath = ["."]`; mypy and ruff check it.

## Case format (`convergence.escapecase/1`)

Strict: unknown keys are errors, nothing is coerced, YAML anchors, aliases, duplicate keys,
and dates are rejected. Cases are validated through JSON exactly as policies are.

```yaml
id: fs-read-secret-001           # unique across all sets; kebab-case
category: filesystem-read        # one of the categories in the coverage table, or "control"
description: >
  Reads a secret file the policy does not grant and copies it to an allowed output.
expect:
  verdict: blocked               # attacks: blocked. Controls: allowed. Enforced by the schema.
  mechanism: landlock-fs         # informational: the expected stopping mechanism
  min_abi: 1                     # Landlock ABI the mechanism needs (0 = every kernel).
                                 # Below it, an escape is a documented limitation.
policy:                          # an inline convergence.policy/1 document
  version: 1
  filesystem:
    read: [/usr, /etc/ld.so.cache, "${WORKDIR}"]
    write: ["${OUT_DIR}"]
    execute: ["${PYTHON}", {path: "${LOADER}", optional: true}]
  environment:
    set: {PATH: /usr/bin:/bin}
payload:
  # Every attack must emit ${REACHED} (flushed) just before its attempt.
  argv: ["${PYTHON}", "-c", "..."]   # exactly one of argv or file
  # file: payload.py                 # .py or .sh, relative to the case file (see below)
  # stdin: "..."                     # optional
oracle:
  type: canary-file-read         # plus that oracle's own keys (strictly validated)
platforms:
  arch: [x86_64, aarch64]        # default: both; other architectures are skipped
  requires: []                   # host preconditions, e.g. [unprivileged-userns]
```

**`payload.file`.** The file is copied into `${WORKDIR}` and run with `${PYTHON}` (`.py`) or
`/bin/sh` (`.sh`). Runner variables inside it are expanded; any other `${name}` is left
alone, because shell scripts use that syntax themselves. In `policy`, `argv`, and `stdin`,
an unknown variable is an error.

### Variables

The runner creates fresh state for every case and exposes it through these variables.
`${HOME}`, `${CWD}`, and `${SCRATCH}` are **policy** variables: they are left for Convergence
to resolve (the unconfined launcher resolves them itself, with `${CWD}` = `${WORKDIR}` and a
fresh scratch directory). A string that is exactly one numeric variable becomes a number,
so `tcp_connect: ["${SINK_PORT}"]` works.

| Variable | Provided by | Meaning |
|---|---|---|
| `${WORKDIR}` | runner | fresh directory; the payload's working directory |
| `${OUT_DIR}`, `${OUT}` | runner | a directory the policy should grant write on, and `output.txt` in it. Everything written here is scanned |
| `${PYTHON}` | runner | the system interpreter, resolved (for example `/usr/bin/python3.12`) |
| `${LOADER}` | runner | the dynamic loader for this architecture, resolved |
| `${REACHED}` | runner | a fresh token an attack must emit just before its attempt |
| `${CANARY_FILE}`, `${CANARY_DIR}` | `canary-file-read` | a secret file outside every grant, and its directory |
| `${FORBIDDEN_PATH}`, `${SENTINEL_FILE}` | `canary-file-write` | a path that must not be created; a file that must not change |
| `${SENTINEL_FILE}` | `canary-delete` | a file that must not be removed, moved, or replaced |
| `${INPUT_FILE}`, `${INPUT_JSON}`, `${INPUT_MODULE}`, `${REPO}` | `workload-output` | inputs inside `${WORKDIR}` carrying a marker (`${REPO}` with `fixture: git-repo`) |
| `${SINK_HOST}`, `${SINK_PORT}`, `${SINK_NONCE}` | `network-sink` (IP) | the harness listener, and data a control must deliver |
| `${SINK_PATH}` / `${SINK_ABSTRACT}` | `network-sink` (`unix` / `unix-abstract`) | a unix-socket listener outside every grant: a path, or an abstract name to connect to with a leading NUL byte |
| `${SERVE_PORT}`, `${SERVE_NONCE}` | `server-reachable` | the port a control must serve on, and what to answer |
| `${SENTINEL_PID}` | `process-read`, `process-signal` | the harness-owned target process |
| `${SENTINEL_SECRET_ADDR}` | `process-read` with `expose_secret_address` | the address of the secret in the sentinel's memory |
| `${ENV_CANARY_NAME}` | `env-leak` | the *name* of the supervisor's secret variable (never its value) |
| `${INHERITED_FD}` | `fd-leak` | the descriptor number open in the supervisor |
| `${MARKER}`, `${MARKER_DIR}` | `exec-probe` | a program planted outside every grant, and its directory |

Secrets the payload must not be able to obtain are never exposed as variables; only their
paths, names, or destinations are.

## Oracles

Every oracle answers one question from ground truth the harness controls: **did the effect
happen?** For an attack, yes means it escaped; for a control, yes means it did its job.
Each oracle implements `setup(dirs) -> Setup` and `check(dirs, evidence) -> Observation`,
and optionally `teardown()`.

| `oracle.type` | Config | Harness setup | Observed when |
|---|---|---|---|
| `canary-file-read` | — | plant a secret file outside every grant | the secret appears in any output channel |
| `canary-file-write` | — | note a forbidden path; plant a sentinel file | the path exists, or the sentinel changed or vanished |
| `canary-delete` | — | plant a sentinel and **hold it open** | the original was unlinked, moved away, replaced, or edited |
| `workload-output` | `fixture: files\|git-repo`, `check: nonce-in-output\|archive`, `require_file` | plant inputs inside `${WORKDIR}` carrying a marker | the marker came out (in stdout or `${OUT_DIR}`; only files if `require_file`; inside an archive for `archive`) |
| `network-sink` | `family: ipv4\|ipv6\|unix\|unix-abstract`, `protocol: tcp\|udp` (IP) or `stream\|datagram` (unix), `require_nonce` | a harness listener: an ephemeral IP port, or a unix socket standing in for a host service | it received a connection or datagram (with `${SINK_NONCE}` if `require_nonce`) |
| `server-reachable` | — | pick a port; poll it from the harness | the harness got `${SERVE_NONCE}` back |
| `process-read` | `allow_ptrace`, and at most one of `secret_in_environment`, `secret_in_mapped_path`, `expose_secret_address` | a sentinel holding a secret in memory only. `secret_in_environment`: also in its environment (`/proc/<pid>/environ`, a ptrace read check rather than an attach check). `secret_in_mapped_path`: the secret is the name of a file the sentinel maps, so `/proc/<pid>/maps` shows it. `expose_secret_address`: the sentinel reports where the secret sits, as `${SENTINEL_SECRET_ADDR}`, so a case can read that address without scanning. There is deliberately no command-line option: `/proc/<pid>/cmdline` is world-readable with no ptrace check, so with `/proc` granted it is a `/proc` reading the threat model leaves out of scope | the secret appears in any output channel |
| `process-signal` | `allow_ptrace` | a sentinel that records `SIGUSR1` in a host file | it was signalled, stopped, or killed |
| `privilege-gain` | — | sample every process's effective uid and capabilities | any process ran with another euid or with capabilities |
| `persist` | — | wait 1 s after the root process ends | any process of the run is still alive |
| `env-leak` | — | put a secret in the **supervisor's** environment | the secret appears in any output channel |
| `fd-leak` | — | open a secret file in the supervisor and pass the descriptor on | the secret appears in any output channel |
| `resource-dos` | `measure: processes\|memory\|cpu\|file-size\|open-files\|wall-clock` | sample processes; measure files and time | the run exceeded the **policy's** limit for that measure |
| `exec-probe` | `marker: elf\|script` | plant a marker program outside every grant | `elf`: its inode was mapped executable in any process. `script`: its secret appears in the output |
| `fd-kind` | `kinds: [io_uring, userfaultfd, perf_event, bpf]` (at least one) | sample every process's anonymous-inode descriptors | a process of the run held one of those kinds (`readlink /proc/<pid>/fd/*`) |
| `namespace-change` | `types: [user, mnt, net, pid, uts, ipc, cgroup, time]` (default all) | record the runner's own namespaces; sample every process's | a process of the run was in a different namespace of a listed type (`pid` and `time` also check `*_for_children`) |
| `key-created` | — | record this user's key count | the count in `/proc/key-users` rose during the run (per user: another process of the same user adding a key would also count) |

Details that matter:

- **Output channels** are stdout, stderr, and regular files under `${OUT_DIR}`. Symlinks are
  never followed when scanning, so a payload cannot point one at a host file and make the
  harness read it.
- **Process membership.** A process belongs to a run if it is the root, in the root's
  session, a descendant of a member, or reparented to the runner. The runner CLI makes itself
  a child subreaper, so a daemon that leaves the session still lands with the runner and is
  seen. Every process is identified by pid *and* start time, so pid reuse cannot confuse it.
- **Sentinels opt in to tracing** (`PR_SET_PTRACER_ANY`, unless `allow_ptrace: false`).
  This takes Yama out of the picture, so a validity run measures whether *Convergence* stops
  the access, not whether Yama happens to.
- **`exec-probe` with `marker: elf`** copies a `sleep` binary to a new inode, named `sleep`
  so that a multi-call coreutils (Ubuntu 26.04's Rust uutils) still runs it as sleep. Setup
  checks that the copy runs both directly and through the dynamic loader, and tries the next
  candidate if not: Ubuntu's uutils refuses to run under `ld.so`, so there the marker is
  GNU's `/usr/bin/gnusleep`. The sampler looks for that inode in executable mappings (`/proc/<pid>/maps`), which is true
  whether the marker was `execve`d or mapped by the dynamic loader, and cannot be faked by
  printing. The payload must keep it running long enough to be sampled, for example
  `${MARKER} 1`.
- **Isolate the mechanism.** An oracle must observe the effect only the case's mechanism can
  stop. A canary read, for example, is stopped by Landlock whatever the seccomp filter does,
  so it cannot test a seccomp rule: use `fd-kind`, `namespace-change`, or `key-created` for
  the syscall-filter categories. The payload must hold the object for about half a second so
  the 20 ms sampler sees it.
- **`resource-dos`** compares measurements with the case's own policy: peak processes added
  beyond the tool's own (minus the launcher's overhead) with `max_processes`, peak per-process resident
  memory with `memory_mb`, peak per-process CPU time with `cpu_seconds`, the largest file
  under `${OUT_DIR}` and `${WORKDIR}` with `max_file_size_mb`, peak per-process descriptors
  with `max_open_files`, and elapsed time with `wall_clock_seconds` plus 2 s grace. The
  measured limit must be set in the policy. Keep the limits small (for example
  `memory_mb: 64`, `max_processes: 8`) and `cpu_seconds` below `wall_clock_seconds`, so an
  unconfined run clearly exceeds the policy before the harness's safety limits stop it.

### The reached marker

Every attack payload must emit the runner's `${REACHED}` token — to stdout (flushed) or to a
file under `${OUT_DIR}` — **immediately before** its attempt. Without it, an attack that was
stopped by something else (a missing grant, a crash at start-up, a typo) would look exactly
like one Convergence contained.

The marker is the payload's own report, so it is trusted only in the safe direction:

- unconfined, an attack that escapes without emitting it is `invalid` (fix the payload);
- under Convergence, an attack that is contained without emitting it is `not-reached`, a
  failure, never a pass;
- an attack that escapes is an escape, marker or not. The marker can never excuse one.

Controls do not need it: their positive oracle already proves they ran. Flush it. Buffered
output is lost if the process is then killed, which would turn a real containment into
`not-reached`.

### Host preconditions

Some behaviour is already prevented by the host before Convergence is involved. Such a case
cannot escape even unconfined, so it can say nothing about Convergence. A case lists what it
needs in `platforms.requires`; the runner probes each once at start-up, in a throwaway
child, by trying the behaviour itself. Where the host lacks it, the case is `not-testable`:
reported, excluded from both rates, and never counted as blocked.

| Precondition | Probe | Lima VM (Ubuntu 24.04, kernel 6.8) |
|---|---|---|
| `unprivileged-userns` | create a user namespace, map ids, and create a mount namespace inside it | refused: mapping ids fails with `EACCES` (AppArmor's unprivileged-userns restriction) |
| `legacy-tiocsti` | `dev.tty.legacy_tiocsti` is 1, or the kernel predates it | refused: it is 0, so TIOCSTI already needs `CAP_SYS_ADMIN` |
| `raw-socket` | create an IPv4 raw socket as the current user | refused (no `CAP_NET_RAW`) |
| `setuid-executable` | run `passwd` (else `su`) for about 0.1 s and observe a changed effective uid; may leave a PAM or audit log entry, so it only runs when a selected case requires it | available |
| `userns-create` | create a user namespace (no mapping, no capabilities needed) | available: Ubuntu's restriction allows creating one and only makes its capabilities unusable |
| `io-uring` | `io_uring_setup` | available (`kernel.io_uring_disabled = 0`) |
| `userfaultfd` | `userfaultfd(UFFD_USER_MODE_ONLY)` | available |
| `unprivileged-bpf` | create a BPF array map | refused (`kernel.unprivileged_bpf_disabled = 2`) |
| `unprivileged-perf` | open a software perf counter on itself | refused (`kernel.perf_event_paranoid = 4`) |

Probes that need a raw syscall get its number from libseccomp, so they are correct on every
architecture. Payloads cannot import Convergence, so a payload that makes a raw syscall must
carry its own per-architecture numbers (see `bpf-perf-keyctl-userfaultfd-001`).

## Launchers

| Launcher | What runs | Environment and descriptors | Deadline |
|---|---|---|---|
| `unconfined` | the payload, through `_limits.py` | the runner's **whole** environment, plus the oracle's supervisor variables and the policy's `set`; the oracle's descriptors are passed on | the harness kills the process group at 2 × `wall_clock_seconds` + 5 s |
| `convergence` | `convergence run --policy <file> -- <argv>` | the supervisor environment and descriptors are handed to `convergence run`, which must empty and close them itself | `wall_clock_seconds` + 15 s |

The unconfined launcher deliberately leaks what a careless supervisor would (environment,
descriptors), because it represents "nothing protecting the tool". That is what lets
`env-leak` and `fd-leak` attacks escape unconfined, which their validity requires. Its only
protection is the **safety envelope** in `_limits.py`: rlimits at four times the policy's
(processes, memory as `RLIMIT_DATA`, address space, CPU, file size, descriptors), memory
capped at half the host's RAM. That keeps a validity run from taking the host down while
still letting it exceed the policy.

`ConvergenceLauncher` checks once whether `convergence run` exists. Until Phase 4 it does
not, and every case is reported `launcher-unavailable`: nothing is executed, and the run
fails.

Output is drained by reader threads that keep at most 1 MiB per stream, so a payload that
floods stdout cannot exhaust the runner.

## Scoring

| Case | Launcher | Effect observed? | Result | Failing? |
|---|---|---|---|---|
| attack | unconfined | yes | `valid` | |
| attack | unconfined | no | `invalid` (the case proves nothing) | yes |
| control | unconfined | yes / no | `valid` / `invalid` | no / yes |
| attack | convergence | no | `pass` | |
| attack | convergence | yes | `escape` (the policy was too loose) | yes |
| attack, kernel ABI < `min_abi` | convergence | yes | `documented-limitation` | |
| control | convergence | yes | `pass` | |
| control | convergence | no | `false-denial` (the policy was too tight) | yes |
| any | convergence | — | `skipped-unenforceable` if `explain` says the policy cannot be enforced here | |
| any | convergence | — | `launcher-unavailable` if `convergence run` does not exist | yes |
| attack | convergence | no, and `${REACHED}` missing | `not-reached` (stopped before its attempt; proves nothing) | yes |
| any | any | — | `not-testable` if the host lacks a `requires` precondition | |
| any | any | — | `skipped-platform`, or `error` if the harness could not run the case | `error`: yes |

- **Escape rate** = escapes / (passes + escapes) among attacks. Documented limitations,
  not-testable cases, skips, and unavailable runs are excluded and listed separately, never
  folded in.
- **False-denial rate** = false denials / (passes + false denials) among controls.
- Both come with Wilson 95% intervals and are reported per set (dev, holdout, controls) and
  per kernel, one report per environment.

## Running

```bash
python -m escape.runner list [--set dev|controls]
python -m escape.runner validity [--set dev --set controls] [--json P] [--markdown P]
python -m escape.runner run --launcher {unconfined,convergence} [--set ...] [--case ID ...] \
                            [--json P] [--markdown P]
python -m escape.runner run --launcher convergence --set holdout --holdout-run
python -m escape.runner seal-holdout
python -m escape.runner verify-holdout
```

The default set is `dev` plus `controls`. Exit status: 0 if no case failed; 1 if any case
escaped, was falsely denied, was invalid, errored, or could not run; 2 for usage or
configuration problems.

## Holdout seal

- `cases/holdout.sha256` lists `<sha256>  <path>` for every file under `cases/holdout/`
  (sorted), then a `<sha256>  MANIFEST` line over those lines. Write it with
  `seal-holdout` when the holdout is written, and commit it.
- `verify-holdout`, a test (`tests/test_escape_schema.py`), and CI all fail if a holdout
  file is added, removed, or changed after sealing, or the manifest is tampered with.
- Any run that includes the holdout — validity or confined — needs `--holdout-run`, first
  re-verifies the seal, and appends one JSON line to `holdout-runs.jsonl` (time, commit,
  kernel, ABI, architecture, launcher, counts, escape rate). `list` refuses the holdout.
- **Discipline:** do not open the holdout cases while implementing or tuning Phase 4. Run
  the holdout once per milestone and report the result as it is.

### Authoring rules

These come from defects found in the first corpus; `build_cases.py` and its tests enforce
the ones they can.

1. **One technique per case, and no duplicates.** Two cases with the same payload, oracle,
   and policy are one case counted twice. The generator refuses them, and a test checks that
   no two development payloads are byte-identical.
2. **Never derive the holdout from the development templates.** A holdout generated from
   the same code is a copy of the development set, and its number is a development number
   under another name. Write it separately, by hand, and seal it.
3. **Isolate the mechanism** (see [Oracles](#oracles)), and grant enough that only it can
   stop the attempt: a different TCP port for port cases, read but not execute for the
   loader case, execute on the setuid helper for the no-new-privileges case.
4. **Setup first, then `reached()`, then the attempt**, and setup writes only to
   `${OUT_DIR}`. Otherwise a setup step the policy denies stops the payload before its
   attempt, and Convergence gets the credit.
5. **Derive paths from variables** (`os.path.relpath('${CANARY_FILE}', '${WORKDIR}')`), not
   from the harness's directory layout.
6. **Edit `build_cases.py`, not the generated files**, then run
   `python -m escape.build_cases`. A test fails if a generated file was edited by hand.
   Hand-written cases may sit beside the generated ones; the generator never touches files
   it did not create.

## Benign controls

Ten controls are in [`controls/`](../controls/), each with what is meant to be the tightest
policy that still lets it work, and a positive oracle: the harness plants a marker inside the
grants and checks that the real output carries it.

| Control | Workload | Oracle |
|---|---|---|
| `control-python-read-write` | Python reads a project file, writes a filtered copy | workload-output (file) |
| `control-git-log` | `git log` on a fixture repository | workload-output (git-repo) |
| `control-shell-pipeline` | `find \| sort \| xargs grep \| sed` to a file | workload-output (file) |
| `control-tar-gzip` | `tar -czf` of the project | workload-output (archive) |
| `control-python-sqlite` | `sqlite3`: create, insert, query | workload-output (file) |
| `control-json-tool` | `python -m json.tool` | workload-output (file) |
| `control-py-compile` | byte-compile a module (a build-like step) | workload-output (file) |
| `control-http-client-allowed-port` | HTTP POST to a granted TCP port | network-sink (require_nonce) |
| `control-tcp-server-allowed-port` | serve one request on a granted TCP port | server-reachable |
| `control-subprocess-spawn` | Python spawns a shell and grep, within `max_processes` | workload-output (file) |

All ten are valid unconfined ([results](results/README.md)). Whether their policies are
tight *enough* to also pass under Convergence is measured in Phase 4; a false denial there is
a finding, and the policy may be corrected, since controls are not sealed. A control running
a real stdio MCP server built with the `mcp` SDK is added in Phase 6, when the SDK becomes a
dependency. Several controls (`tar`, `git`) touch file metadata, which is the evidence the
Phase 4 decision on mitigating `chmod`/`chown`/`utime` needs.

## What is done, and what is next

- **Done:** the harness and its tests; ten valid controls; 47 distinct development attacks
  (45 valid, 2 not testable on the tested hosts); a 26-case independently authored holdout,
  valid unconfined and sealed; and the validity reports and run log.
- **Phase 4:** build `convergence run`; drive the dev escape rate to zero or document each
  remaining escape here and in THREAT_MODEL.md; measure the false-denial rate; then run the
  holdout once under Convergence and commit the result as it is. The holdout's earlier
  entries in `holdout-runs.jsonl` are unconfined validity runs, not that run.
